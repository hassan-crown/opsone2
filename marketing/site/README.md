# موقع OpsOne التسويقي

موقع ثابت يبيع OpsOne لأصحاب المنشآت السعودية التي تبيع منتجات جاهزة وحسب الطلب من معرض أو متجر إلكتروني.

- **التقنية:** HTML وCSS وJavaScript بلا إطار عمل، والخطوط والصور محلية.
- **اللغة:** عربي فقط، والاتجاه من اليمين أولًا.
- **الهدف:** إجراء واحد هو طلب عرض تجريبي.
- **الصفحات:**
  - الصفحة الرئيسية.
  - تسع صفحات قطاعات في `solutions/`.
  - الصفحات القانونية (مسودات): الخصوصية والشروط وملفات تعريف الارتباط.
  - صفحة «شكرًا» وصفحة 404.

يحلّ هذا الموقع محل صفحة الهبوط الأولى (`marketing/landing/`، ADR-0034)، وهي باقية في تاريخ git. القرار في ADR-0044.

## التشغيل محليًا

```bash
python3 -m http.server 8080 --directory marketing/site
```

ثم افتح `http://localhost:8080`.

## البناء

```bash
node marketing/site/build-site.mjs
```

يلزمه Node فقط، بلا اعتماديات. يقوم الأمر بما يلي:

1. يكتب في `index.html` الأجزاء المشتركة، بين علامات `<!-- @name -->`:
   - الهيدر والفوتر وبطاقات القطاعات.
   - شريط الموافقة.
   - قسم «الباقات».
2. يبني صفحات القطاعات التسع من `solutions/<نشاط>/data.json`، ومن `compose.mjs` إن وُجد.
3. يكتب صفحات `privacy/` و`terms/` و`cookies/` و`thanks/` و`404.html`.
4. يكتب `sitemap.xml`. قيمة lastmod لكل صفحة هي تاريخ آخر commit عدّل مصادرها، أو تاريخ اليوم إن كانت فيها تعديلات لم تُحفظ.

لا تعدّل الملفات المولّدة يدويًا. الملفات المولّدة هي:
- كل `solutions/*/index.html`.
- الصفحات البسيطة.
- ما بين العلامات في `index.html`.

## الملفات

| الملف | ما هو |
|---|---|
| `index.html` | الصفحة الرئيسية. محتواها مكتوب يدويًا، ما عدا ما بين العلامات. |
| `styles.css`، `main.js` | تصميم الرئيسية وحركتها. |
| `site.js` | ما تشترك فيه كل الصفحات: <ul><li>قائمة «الحلول» وقائمة الجوال.</li><li>زرّا واتساب والاتصال.</li><li>قسم «الباقات».</li><li>رابط المطوّر.</li><li>نموذج طلب العرض مع حالة «شكرًا».</li></ul> |
| `tags.js` | أدوات القياس والإعلان والأحداث. لا يُحمَّل شيء منها إلا بعد الموافقة. |
| `config.js` | **الملف الوحيد الذي يُملأ قبل الإطلاق.** |
| `site/sectors.json` | قائمة القطاعات: الاسم، وسطر القائمة، وسطر البطاقة، والصورة، و«قطاعات قريبة». |
| `site/partials.mjs` | الأجزاء المشتركة: <ul><li>الهيدر والفوتر.</li><li>البطاقات و«قطاعات قريبة».</li><li>شريط الموافقة.</li><li>«الباقات».</li></ul> |
| `site/pages.mjs` | نصوص الصفحات البسيطة وقالبها. |
| `solutions/build.mjs`، `sector.css`، `sector.js` | قالب صفحة القطاع. |
| `solutions/<نشاط>/` | ملفات القطاع: <ul><li>`data.json` للمحتوى وSEO.</li><li>`compose.mjs` وملفات CSS وJS الخاصة بالقطاع، إن وُجدت.</li><li>الصور، و`credits.json`، و`RESEARCH.md` الذي يربط كل ادعاء بالكود.</li></ul> |
| `assets/` | الخطوط (IBM Plex Sans Arabic مع OFL)، والشعار، والصور، ومقاطع الفيديو، وGSAP. |
| `robots.txt`، `sitemap.xml`، `site.webmanifest` | الزحف والتثبيت. |

الوثائق خارج المجلد المنشور، في `marketing/docs/`:

| الملف | ما فيه |
|---|---|

## SEO

**في كل صفحة:**
- title وdescription.
- canonical وhreflang (`ar` و`x-default`، ولا نسخة إنجليزية).
- OG وTwitter بصورة موجودة: صورة عامة للرئيسية، وصورة خاصة بكل قطاع.
- theme-color، وfavicon (SVG وPNG 32)، وapple-touch-icon، والـ manifest بأيقونتي 192 و512.
- `lang="ar" dir="rtl"`.

**JSON-LD:**
- الرئيسية: Organization وWebSite وSoftwareApplication.
- صفحة القطاع: SoftwareApplication مع audience، وFAQPage، وBreadcrumbList.

**قيود SEO لكل قطاع (`data.json` ← `seo`):**
- `title` في حدود 60 حرفًا.
- `h1` هو سطر كلمات البحث فوق العنوان.
- `snippet` في حدود 155 حرفًا.
- `description` يُستعمل في JSON-LD.

**صفحات خارج الفهرسة (noindex، خارج السايت ماب):** الصفحات القانونية حتى المراجعة، وصفحة «شكرًا»، وصفحة 404.

## القياس والموافقة

**شريط الموافقة (`tags.js`):**
- يظهر فقط إذا مُلئ معرّف واحد على الأقل.
- يسأل عن غرضين منفصلين:
  - القياس: GA4 وGTM.
  - الإعلانات: Google Ads وMeta وTikTok وSnap وLinkedIn.
- زرّا «رفض الكل» و«قبول الكل» بالوزن نفسه.
- رابط «ما الذي نستخدمه» يفتح صفحة الكوكيز.
- يُحفظ الاختيار مع تاريخه.
- «إعدادات الخصوصية» في الفوتر تعيد فتحه. سحب غرض يعيد تحميل الصفحة دون أدواته.
- Google Consent Mode v2 مرفوض كله في البداية.
- صُمّم ليتوافق مع نظام حماية البيانات الشخصية: موافقة محددة الغرض ومعلومة وقابلة للسحب. المراجعة القانونية مطلوبة.

**الأحداث:** تُرسل فقط إلى الأدوات المحمّلة، وتحمل كلها `sector` و`utm_*`.

| الحدث | متى يُرسل |
|---|---|
| `page_view` | config في GA4، أو GTM |
| `sector_view` | عند فتح صفحة قطاع |
| `scroll_depth` | عند 25 و50 و75 و100% من الصفحة |
| `demo_cta_click` | عند النقر على كل زر طلب عرض |
| `click_whatsapp`، `click_call` | عند النقر على زر واتساب أو الاتصال |
| `generate_lead` / `demo_request` | عند نجاح إرسال النموذج، ومعه تحويلات Google Ads وMeta Lead وTikTok SubmitForm وSnap SIGN_UP وLinkedIn |

**حفظ مصدر الزيارة:**
- تُقرأ `utm_*` و`gclid` و`fbclid` من الرابط في أي صفحة.
- تبقى طوال الزيارة عند الانتقال بين الصفحات.
- تُرسل مع النموذج في حقول مخفية.

## الأداء

### Lighthouse (قبل جولة الإصلاح)

شغّلته جلسة المدير على الجوال، عبر `python http.server`، أي بلا ضغط وبلا تخزين مؤقت:

| الصفحة | الأداء | سهولة الوصول | أفضل الممارسات | SEO |
|---|---|---|---|---|
| الرئيسية | 77 | 97 | 100 | 92 |
| المطابخ | 83 | 100 | 100 | 92 |
| الألمنيوم | 79 | 100 | 100 | 92 |

### ما أُصلح بعده

| الملاحظة | الإصلاح |
|---|---|
| الخطوط | `font-display: swap` للأوزان الأربعة. يبقى preload للوزنين 400 و700. |
| الأيقونات | ملف واحد مخزّن `assets/icons.svg` بدل sprite داخل كل صفحة. يوفّر نحو 11 كيلوبايت و237 عنصر DOM في كل صفحة. |
| CSS | <ul><li>يكتب البناء نسخًا مصغّرة `*.min.css`، والملفات المقروءة `*.css` تبقى المصدر.</li><li>لكل صفحة يُحذف ما لا تستعمله من القواعد (`site/purgecss.mjs`): تبقى القاعدة إن كان كل اسم class أو id فيها موجودًا في HTML الصفحة أو في JS الذي تحمّله.</li><li>قواعد الشاشة الأولى (الهيدر والبطل والقسم الذي يليه، ونافذة الموافقة، وزر واتساب) تُكتب inline في `<head>`.</li><li>البقية في `page.bundle.min.css` بجانب الصفحة، تُحمَّل غير حاجبة (`media="print"` يحوّلها `site.js`، مع `<noscript>`)، فلا يبقى أي ملف CSS حاجب للعرض.</li><li>الصفحات بلا بطل (القانونية و«شكرًا» و404) تأخذ كل CSS inline.</li></ul> |
| crawlable-anchors | روابط واتساب والاتصال لها `href` حقيقي إلى أن تُضبط الأرقام. |

التحقق:
- الصفحات بعد الإصلاح مطابقة بالبكسل لما قبله: 10 لقطات كاملة الطول على 1440 و375. الفرق الوحيد في الرئيسية هو إصلاح التباين المقصود.
- الشاشة الأولى بالـ CSS الحرج وحده (الملف غير الحاجب ممنوع) مطابقة لها مع الملف: 12 صفحة على 1440 و768 و412.

### لم يُصلح من الكود

- **الضغط وcache-ttl:** من الخادم. Brotli يصغّر `styles.min.css` من 79 كيلوبايت إلى نحو 13، والرئيسية من 99 كيلوبايت إلى نحو 20. التفاصيل في `marketing/docs/hosting.md`.
- **تصغير JS:** لم يُنفَّذ بلا أداة، والملفات كلها `defer` فلا تحجب العرض.
- **حجم DOM في الرئيسية:** انخفض بإزالة الـ sprite. ما بقي هو محتوى أجزاء المنتج المعتمدة.

### قياس مخبري بعد الإصلاح

المتصفح Chromium مع خنق شبيه بإعدادات Lighthouse:
- الجوال: معالج أبطأ 4 مرات، وشبكة 1.6 Mbps بتأخير 150 ms.
- سطح المكتب: من دون خنق.

الأرقام مؤشرات وليست درجات Lighthouse. يُعاد Lighthouse على الخادم الحقيقي مع الضغط قبل الإطلاق.

| الصفحة | LCP جوال | LCP سطح المكتب | CLS | TBT |
|---|---|---|---|---|
| `/` | 0.44 ث (FCP ‏0.44) | — | 0.003 | 0 |
| `/solutions/kitchens/` | 1.01 ث (FCP ‏0.46) | — | 0.027 | 0 |
| `/solutions/aluminium-glass/` | 1.44 ث (FCP ‏0.47) | — | 0.005 | 0 |

(قبل CSS الحرج: ‏LCP الجوال 2.22 و1.84 و2.05 ث.)

**ما يبقى من قبل:**
- صورة البطل مسبقة التحميل بـ `fetchpriority="high"` و`srcset`، ولا تحمل `lazy`.
- الصور تحت الطيّة `loading="lazy"`.
- مقاطع الفيديو `preload="none"`.
- GSAP على الشاشات العريضة فقط.
