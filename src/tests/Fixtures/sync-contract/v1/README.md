# OPSONE-SYNC-v1 contract vectors

Shared with `opsone2` batch T4 (copy this folder to `src/tests/Fixtures/sync-contract/v1/`). Protocol: ADR-0047 in
`opsone2`, central side: `docs/decisions/0010-license-sync-and-fleet-health.md`.

All `.json` files are generated by `php artisan sync:contract-vectors` and checked byte for byte by
`tests/Feature/Sync/SyncContractTest.php`. Do not edit them by hand. This README is hand-written.

## Request

`POST https://sync.<domain>/v1/sync`, body = the heartbeat JSON (≤ 16 KB), with headers:

| Header | Value |
| --- | --- |
| `X-OpsOne-Deployment` | the deployment ULID (26 chars) |
| `X-OpsOne-Timestamp` | Unix seconds, within ±300 s of the central clock |
| `X-OpsOne-Nonce` | 16 random bytes, unpadded base64url (22 chars), never reused within 15 minutes |
| `X-OpsOne-Signature` | Ed25519 detached signature, unpadded base64url (86 chars) |

Signed message (`\n` = LF, no trailing newline):

```
"OPSONE-SYNC-v1\n" . "POST" . "\n" . "/v1/sync" . "\n" . deployment_id . "\n" . timestamp . "\n" . nonce . "\n" . hex(sha256(body))
```

- The method is upper case; the path has no query string (the central app rejects any query string).
- `hex(sha256(body))` is lower-case hex of the exact bytes sent.

## Files

- `keys.json` — **public test keypair** (derived from a fixed seed). The central app refuses to register it outside
  local/testing. Never use it for a real deployment.
- `vectors.json` — each vector: headers, `body_base64`, `body_sha256`, the exact `message`, and `signature_valid`
  (signature check only, against `public_key_base64`). Invalid vectors cover a tampered body, another path, another
  deployment, another timestamp, a lower-case method, a wrong key, and the licence context prefix.
- `heartbeat.schema.json` — JSON Schema (2020-12) of `schema_version = 1`. Every object is closed and every
  property required: send `null` where a value is unknown, never omit or add a key.
- `heartbeat.example.json` — a valid heartbeat (the body of the `heartbeat` vector, compact-encoded).
- `heartbeat.invalid.json` — bodies rejected with 422 and the error path the central app reports.
- `responses.json` — response shapes.

## Responses

| Status | Body | Facility behaviour (ADR-0047 §6) |
| --- | --- | --- |
| 200 | `{"license_id": "...", "envelope": "<envelope JSON text>"}` | verify and install via `LicenseInstaller` |
| 200 | `{"license_id": "...", "envelope": null}` | already on the newest licence: write nothing |
| 200 | `{"license_id": null, "envelope": null}` | nothing issued yet |
| 401 | `{"error": "unauthorized"}` | identical for every authentication failure |
| 413 | `{"error": "payload_too_large"}` | |
| 422 | `{"error": "invalid_heartbeat", "errors": {"<dot.path>": ["..."]}}` | schema drift: fix the collector |
| 429 | `{"error": "too_many_requests"}` + `Retry-After` | |

Any non-200 leaves the licence state unchanged; record `last_sync_error` and retry at the next scheduled run.

## الكتلة الاختيارية `ai` (C-AI، ADR-0013)

`heartbeat.ai.example.json` هو الـ heartbeat نفسه مع كتلة `ai`: `period` (YYYY-MM بشهر المنشأة)، و`credits_used`، و`cost_usd_micro`،
و`suggestions_accepted`، و`models[]` (`model`, `input_tokens`, `output_tokens`, `cached_tokens`). الكتلة اختيارية: المنشأة بلا مساعد
تحذفها، والـ heartbeat بلا `ai` صالح كما كان. مجاميع فقط، ولا حقل نص ولا بيانات عملاء (الأجسام مغلقة). والتقرير الأحدث لنفس
`period` يستبدل الأقدم.
