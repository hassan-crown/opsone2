# Deployment — دليل النشر

## المتطلبات

- Git repository قابل للوصول، Docker Compose v2، أسرار مستقلة لكل بيئة، مستخدم نشر صحيح UID/GID.
- شبكة Traefik `proxy` موجودة مسبقًا مع `web`, `websecure`, `letsencrypt`.
- سجلات DNS صالحة للنطاقات، وشهادة TLS تعمل.
- نسخ احتياطية للـ DB والملفات الخاصة وتحقق من استعادتها قبل تحديثات خطرة.

## الفحوص السابقة للنشر

```bash
./manage.sh config
./manage.sh ps
# تأكد من كفاءة قاعدة البيانات والأقفال والصلاحيات ومن خلو الشجرة من التغييرات
```

الـ `deploy` الحالي يقوم بـ Git fast-forward pull ثم بناء الصور، تشغيل الخدمات، تثبيت Composer، تشغيل migrations، بناء الواجهة، وبدء الـ Worker/Scheduler. **هذا تسلسل غير ذري قد يسبب انقطاعًا لحظيًا أو اختلافًا مؤقتًا بين الكود والأصول**.

## نقطة أمان إلزامية

لا تشغّل `./manage.sh deploy` على الإنتاج قبل الموافقة على migrations والنسخ الاحتياطية، والتأكد من التوافق بين النسخة السابقة والجديدة ومن أن قيمة APP_DEBUG=false، ووضع خطة rollback. لا تستخدم `migrate:fresh` أو `down-volumes` في الإنتاج.

## الاسترجاع

- التراجع عن الكود وحده ليس كافيًا إذا أصبحت Migration غير متوافقة.
- يجب وجود إصدار مستقر سابق من الصور/الكود ونسخة DB عند التغييرات الخطرة.
- للأنظمة الحرجة يوصى بترقية طريقة النشر إلى صور ثابتة (Immutable Images) مع release switching.
