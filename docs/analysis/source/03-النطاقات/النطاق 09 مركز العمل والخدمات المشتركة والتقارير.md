# النطاق 09: مركز العمل والخدمات المشتركة والتقارير

**الحالة: مغلق مبدئيًا بعد مراجعة الربط؛ الاعتماد النهائي لمالك المنتج، وتستخدمه بقية النطاقات دون تكرار السجلات.**

## الهدف والحدود

تقليل البحث والمتابعة اليومية: يرى كل شخص ما يحتاج تدخله وينجزه من سياقه، مع مواعيد واضحة ومساعدة داخل المنصة وسجل موثوق. لا يشمل تحليلات تنبؤية أو تكامل مراسلات مفتوح.

## أجزاء النظام ضمن النطاق

| الجزء | ما يشمله |
| --- | --- |
| مركز العمل والقرارات | مطلوب المستخدم وأسباب التعطل والمهام والمواعيد. |
| الجدولة | زيارات القياس والتركيب والتسليم وتوافر الموظفين أو فرق بسيطة. |
| الإشعارات | درج وقراءة وروابط إجراءات وتذكير مضبوط. |
| المعرفة والدعم | صفحة «المساعدة» داخل المنصة، ومقال لكل صفحة يفتحه زر «؟»، و«ما الجديد» لكل إصدار، وتذاكر العملاء. |
| الملفات والتدقيق والبحث | صلاحيات ومراجع وأثر تغييرات وبحث في السجلات المسموحة. |
| التقارير | تشغيل وتحصيل وأعمار مستحقات ومخزون ومبيعات وعمولات وإلغاءات وتصدير أساسي. |

## ارتباطات تتبع نطاقات أخرى

- **01:** الحساب واللغة والمظهر والصلاحيات ونطاق البيانات.
- **02 إلى06:** السجلات الأصلية والأحداث المالية والتشغيلية؛ المركز والبحث والتقارير تقرؤها ولا تنشئ حالات بديلة.
- **07:** إشعارات العميل ومواعيده ومستنداته وتذاكره.
- **08:** تنبيهات الاشتراك والتجهيز والتجديد وسجل نشر كل جهة.

## قواعد العمل

### مركز العمل

- الرئيسية بحسب الدور: مسؤول المنشأة يرى التعطلات والقرارات والتحصيل والمواعيد، والموظف يرى أعماله، ومشرف القسم يرى صندوق قسمه.
- «تحتاج قرارك» ليست نسخًا من الإشعارات؛ تجمع القرارات المفتوحة من مصدرها وتزول عند حسمها، مع الطلب والسبب ومدة الانتظار والأثر والإجراء المتاح.
- أولوية العرض: ما يمنع التزامًا قريبًا، ثم المتأخر، ثم الأقدم. يظهر الأثر المالي عند وجود مبلغ معروف فقط؛ لا يخترع ترتيبًا ذكيًا أو مبلغ خسارة.
- الإجراءات السريعة مثل تأكيد إثبات دفع أو إسناد مهمة أو فتح اعتماد تستخدم الصلاحية والتحقق نفسيهما داخل السجل.
- ملخص الطلب يبين أين وصل والخطوة التالية وما يمنعها، مع العميل والمسؤول والمستندات المهمة وسجل النشاط. التفاصيل تفتح عند الحاجة دون ازدحام.
- طلب بلا مسؤول أو مهمة بلا منفذ يظهران للمتابع المعلوم. لا نقترح توزيعًا آليًا أو حساب حمل متقدم؛ تظهر قائمة المؤهلين وعدد أعمالهم المفتوحة للمساعدة في القرار.

### الجدولة

- موعد واحد مرتبط بالطلب ونوع الزيارة والعنوان والمدة والموظف أو فريق مسمى من أعضاء فعليين والفرع والحالة.
- حالات الموعد: مقترح، بانتظار التأكيد، مؤكد، تم، ملغى. التأخر وعدم الحضور علامتان للمتابعة وليسا إتمامًا.
- يتحقق النظام من التعارض عند الحفظ أو التغيير؛ الموعد المؤكد يحجز الوقت، والاقتراح لا يضمنه. يعاد التحقق ذريًا عند التأكيد أو اعتماد بديل. التعارض يظهر تنبيهًا ويحفظ المقترح معه؛ تأكيد موعد متعارض يتبع إعداد المنشأة «المواعيد المتعارضة»: «السماح بسبب» (افتراضي) يتيحه لصاحب P-54 ضمن نطاقه بسبب إلزامي وإشعار المنفذ وعلامة «متعارض» على المواعيد المتداخلة، و«منع» لا يتيحه. تأكيد العميل P-70 لا يتجاوز التعارض، ويحال للمخول دون كشف مواعيد الآخرين. تغيير السياسة لا يلغي المواعيد السابقة، وتزال العلامة عند زوال التعارض مع حفظ سجل السماح. تعديل السياسة يتطلب P-02.
- يستطيع الموظف طلب تأكيد من العميل، أو تسجيل تأكيد هاتفي مع الطريقة، أو إتاحة فترات محددة للاختيار. الطلب لا يصبح موعدًا مؤكدًا بمجرد اقتراح العميل.
- تعديل الموعد يوضح السبب ويشعر المعنيين ويحفظ السابق؛ لا يغير مواعيد أخرى أو مدة التصنيع تلقائيًا.
- عرض يومي وأسبوعي ومرشحات بسيطة، مع عنوان قابل للفتح في الخرائط. لا تتبع حي للفنيين أو تحسين مسارات أو محرك طاقة إنتاجية.

### الإشعارات والتذكير

- أحداث الإصدار: إسناد أو إعادة إسناد، مستند ينتظر العميل، طلب تعديل أو اعتماد، إثبات دفع ينتظر المراجعة، تأكيد تحصيل، موعد أو تغييره، تأخر متطلب، ملاحظة تسليم، تحديث تذكرة، اشتراك وتجديد، طلب إلغاء وقراره، قرار مرتجع وطلب استكماله، رد مالي ونتيجته، وتعثر تسوية أو صرف عمولة للمخول المعني فقط.
- القنوات الخارجية: البريد وSMS عبر حسابات الجهة لدى مزوديها، ويوفر OpsOne الربط فقط. الإشعارات الفورية للتطبيق اختيارية لاحقًا، ولا تكامل WhatsApp.
- زر اتصال أو مشاركة الجهاز يفتح وسيلة التواصل المتاحة، ولا يعد سجل إرسال آلي أو إثبات وصول للعميل؛ مشاركة الجهاز ليست تكامل WhatsApp أو قناة آلية.
- درج جانبي مرتب بالأحدث وفواصل خفيفة، مع غير مقروء وتحديد الكل كمقروء وفتح السجل المعني. القراءة لا تنجز المهمة.
- تذكير تلقائي واحد يوميًا كحد أقصى لكل متطلب متأخر ومستلم، وقبل الموعد بيوم، مع إيقافه عند تحقق الحاجة. تتجنب المكررات وتراعى المنطقة الزمنية وساعات الإرسال.
- الرسالة تحدد المطلوب ورابطه دون أسرار أو كشف بيانات لغير المستلم. إعادة المحاولة لا تكرر الإرسال المؤكد؛ يظهر فشل القناة للمسؤول ولا يفشل الإجراء الأصلي.

### المعرفة والدعم

- مساعدة داخل المنصة للمستخدمين المسجلين فقط، بالعربية والإنجليزية، منظمة حسب المهام والأقسام؛ تشرح المطلوب والصلاحيات والأخطاء والحالات الشائعة. لا دليل عام خارج الحساب.
- يكتب فريق المعرفة المقال في محرر نص واحد يضيف ما يسمح به الدليل فقط: عنوان، قائمة، خطوات، ملاحظة، صورة، رابط لمقال، دون ألوان أو خطوط. لكل مقال الصفحات التي يفتحه منها زر «؟»، و«ما الجديد» بنود قصيرة لكل إصدار: جديد، تحسين، إصلاح.
- بحث في العنوان والمحتوى والمرادفات مع مقتطف وموضع النتيجة، ومراعاة اختلاف الكتابة العربية. لا تعد بفهم أي سؤال.
- كل صفحة تشغيل لها مساعدة مرتبطة بها. كل تطوير أو تغيير يؤثر في الاستخدام يتطلب تحديث المعرفة والتحقق من نتائج البحث قبل اعتباره مكتملًا.
- تذكرة العميل: الطلب إن وجد، والنوع (مشكلة، سؤال، طلب، أخرى)، والموضوع والوصف والمرفق والحالة. المسؤول هو مسؤول الطلب، وفي التذكرة بلا طلب هو «مسؤول التذاكر العامة» من إعدادات المبيعات، والمالك افتراضيًا؛ يجب أن يكون المسؤول نشطًا مخولًا بـ P-59 داخل النطاق، وإلا تحال المتابعة للمالك. تظهر في «العملاء»، تبويب «التذاكر»، وفي «مهامي» عند المسؤول. الزائر بلا حساب يسأل من «تواصل معنا» كاهتمام. الحالات جديدة وقيد المعالجة وبانتظار العميل ومحلولة ومغلقة؛ الرد بعد الحل يعيد فتح الأصل ويشعر المسؤول، دون كشف ملاحظات داخلية أو إسقاط نزاع مالي.
- مشكلة عميل المنشأة تصل إلى فريقها. مشكلة تشغيل المنصة أو الترخيص تحال لدعم OpsOne دون كشف ملفات العميل افتراضيًا.

### البحث والملفات والتدقيق

- بحث عام برقم الطلب أو اسم العميل أو الجوال أو رقم مستند، ضمن صلاحية المستخدم فقط. لا يظهر عدد نتائج أو مقتطف يكشف سجلًا محجوبًا.
- لكل ملف مرجع ونوع وصلاحية ورابط وصول مضبوط. منع الامتدادات الخطرة وتحديد الحجم وفحص الرفع قبل عرضه، وعدم استخدام عنوان تخزين عام للملفات الخاصة.
- لا يحذف ملف مثبت لاتفاق أو تحصيل أو تسليم بحذف مرفق عادي. تحفظ النسخة المطلوبة للإثبات دون إدارة إصدارات لجميع الملفات.
- سجل النشاط ملخص مقروء للتواصل والقرارات والتغييرات، وسجل التدقيق التفاصيل المسموحة. لا تخلط الملاحظة الداخلية برسالة العميل.
- يسجل الفاعل والوقت والفعل والقيمة السابقة واللاحقة والسبب عند الحاجة؛ لا تتيح صلاحية الإدارة العادية تعديل سجل التدقيق.
- دعم OpsOne لا يدخل بيانات الجهات دون تفويض دعم محدد المدة والنطاق والمسؤولية وتسجيل الدخول والأفعال. يطلب الدعم التفويض من رده على الطلب، ويمنحه المالك أو يرفضه أو يسحبه من «تفويضات دعم OpsOne» فتنتهي الجلسة. تظهر جلسة الدعم بشريط ثابت بنطاقها ومدتها المتبقية وزر إنهاء، وتُعرض أرقام عملاء المنشأة مقنّعة. المشترك قبل التسليم يراسل الدعم بالبريد.

### التقارير والتشغيل

- تقارير أساسية للجميع: الطلبات حسب الحالة والمرحلة، المتأخر وغير المسند، مواعيد اليوم، قيمة الاتفاقات والتحصيل والمستحق وأعماره، المخزون والناقص والتوريد المتبقي.
- المقارنات المجمعة بين الفروع والأقسام ميزة باقات أعلى؛ لا تحجب البيانات اللازمة لاستكمال العمل اليومي.
- تعريف المؤشرات ثابت ويظهر نطاق التاريخ والفرع. لا يجمع إجمالي الطلبات المترابطة مع مرجع الشراء كمبلغ ثالث.
- تصدير منظم بصلاحية، مع المرشحات نفسها وعدم كشف التكلفة لمن لا يملكها.
- نسخ احتياطي يومي مشفر لكل جهة مع سياسة احتفاظ معتمدة وفحص استعادة قبل الإطلاق وبعد تغييرات البنية. تعالج فشل الوظائف والرسائل والمدفوعات بتسجيل وتنبيه وإعادة محاولة مضبوطة.

## متابعة المبيعات والإلغاء

- يميز التقرير الاهتمام المحول عن اتفاق البيع والتسليم والإلغاء؛ تحويل الاهتمام ليس نجاح مبيعة تلقائيًا.
- يعرض للمخول طلبات تجاوز الخصم وإلغاء العميل مع الإجراء المباشر. يبلغ العميل بنتيجة الإلغاء، ولا يكرر الإشعار أو القرار عند إعادة الحدث.
- المبيعات يرى مبيعاته وروابطه وكشف عمولته، والإدارة ضمن صلاحياتها. التقرير يقرأ استحقاقات المالية ولا يحتسب عمولة بديلة.

تغطية الإعدادات وضوابطها موحدة في قسم «الإعدادات الدائمة وتغطيتها» داخل [الـ SRS متطلبات النظام الكامل](../02-%D9%88%D8%AB%D8%A7%D8%A6%D9%82%20%D8%A7%D9%84%D8%AA%D8%AD%D9%84%D9%8A%D9%84/SRS-%D9%85%D8%AA%D8%B7%D9%84%D8%A8%D8%A7%D8%AA%20%D8%A7%D9%84%D9%86%D8%B8%D8%A7%D9%85%20%D8%A7%D9%84%D9%83%D8%A7%D9%85%D9%84.md). تبقى قواعد كل إعداد في نطاقه المالك؛ يتولى كلود تجميعه وتسميته وتحديد موضعه الأنسب في تجربة الاستخدام دون إلزام بتقسيم واجهات مطابق للنطاقات.

## معايير القبول

- الـ **SHR-01:** إنجاز قرار من مصدره يزيله من قائمة المطلوب، ولا تنجزه قراءة الإشعار.
- الـ **SHR-02:** موعدان متعارضان للمورد نفسه لا يؤكدان معًا في وضع المنع؛ في وضع السماح يحتاج التأكيد P-54 وسببًا وإشعار المنفذ وعلامة واضحة. العميل لا يتجاوز التعارض؛ طلب تغيير لا يلغي الأصلي قبل اعتماد البديل.
- الـ **SHR-03:** تذكير التحصيل يتوقف بعد التأكيد، ولا يتكرر بسبب إعادة حدث.
- الـ **SHR-04:** البحث والمرفق والتصدير تحترم النطاق نفسه، ولا تكشف سجلات خارج الصلاحية.
- الـ **SHR-05:** البحث بكلمة واردة في محتوى مقال يعرض موضعًا مناسبًا، وتغيير ميزة دون تحديث المعرفة لا يغلق.
- الـ **SHR-06:** تقرير التحصيل يطابق الدفعات المؤكدة بعد التصحيحات والاسترداد، ولا يحسب الإثبات المعلق.
- الـ **SHR-07:** تذكرة العميل مرتبطة بطلب مسموح له أو عامة بلا طلب؛ تصل للمسؤول المحدد، وتبقى خاصة بصاحبها ومخولي معالجتها. الملاحظة الداخلية لا تصل إليه، وردّه بعد الحل يعيد فتح الأصل.
- الـ **SHR-08:** تعثر إشعار لا يلغي التحصيل أو الاعتماد، والاستعادة المجربة تعيد بيانات جهة دون أخرى.
