# النطاق 07: الموقع ومساحة العميل

**الحالة: مغلق مبدئيًا بعد مراجعة الربط؛ الاعتماد النهائي لمالك المنتج، والتطبيق الجوال تنفيذ لاحق بالخدمات نفسها.**

## الهدف والحدود

موقع يعرض نشاط المنشأة ويستقبل اهتمام العميل، ومتجر جاهز عند الاشتراك بوحدته، ومساحة عميل تشرح المطلوب وتتيح تنفيذه دون متابعة مرهقة. لا تشمل إدارة المنشأة عبر التطبيق.

## أجزاء النظام ضمن النطاق

| الجزء | ما يشمله |
| --- | --- |
| موقع المنشأة | الهوية والمحتوى والصفحات وكتالوج العرض ونماذج الاهتمام. |
| محرر الصفحات | محتوى وأقسام جاهزة ومسودة ومعاينة ونشر وحماية الصفحات. |
| الثيم والهوية | Alpha افتراضي، وشعار وأيقونة ولون علامة ووضع عرض الموقع، بمعاينة وتطبيق واستعادة. |
| متجر الجاهز | سلة وكوبون أو خصم معتمد، وشراء مباشر أو من رابط موظف، ودفع وتسليم وفق الاستحقاق. |
| حساب العميل | الهوية وبيانات التواصل والعناوين والجلسات والتفضيلات. |
| مساحة الطلب | المطلوب من العميل والرحلة والاعتمادات والمواعيد والمال والمستندات والدعم. |

## ارتباطات تتبع نطاقات أخرى

- **01 و02:** الوصول وملف العميل والكتالوج والطلب وأسعار البيع.
- **03 و04:** الحالة العامة ومطلوب العميل والمستند المعروض واعتماده.
- **05 و06:** الدفع والإثبات والفاتورة والتسليم وتوفر الجاهز.
- **08:** الترخيص والباقات وإيقاف المتجر وتفعيل مساحة المنشأة.
- **09:** الإشعار والجدولة والمعرفة والدعم والبحث والملفات.

## قواعد العمل

### الموقع والمحتوى

- لكل جهة موقع بهويتها ومحتواها ولغتيها؛ شعارها لعملائها، مع نسبة تشغيل مناسبة لـOpsOne. واجهة الإدارة وموقع الاشتراك يستخدمان هوية OpsOne.
- المخصص يعرض أعمالًا ومنتجات وخيارات للتعريف، ويقدم «اطلب تواصلًا» أو «أرسل احتياجك». لا يفرض تسعيرًا فوريًا أو سلة لمنتج يحتاج اتفاقًا.
- نموذج الاهتمام مختصر: الاسم والجوال والبريد والنشاط أو الاحتياج ورسالة ومرفق اختياري. يحفظ الاهتمام مرة واحدة ويعطي مرجعه، ولا يشترط حسابًا مسبقًا.
- الموظف يستطيع فتح طلب مخصص مباشرة للعميل، ثم يدعوه لمتابعته. لا يلزم العميل إعادة إنشاء طلبه على الموقع.
- المحرر يستخدم أقسام نظام التصميم فقط، مع المحتوى والصور والترتيب والإظهار المتاح؛ لا كود حر ولا محرر لشاشات التشغيل.
- سياسات الصفحات: صفحات محتوى تضاف وتؤرشف وتستعاد، ورابط المؤرشفة يحول للرئيسية؛ صفحات تحرر دون أرشفة أو تعطيل؛ وصفحات نظام لا تحرر أو تؤرشف أو تحذف أو تعطل. لا حذف نهائي ضمن وظائف المحتوى؛ الاستعادة تعيد الصفحة مسودة للنشر الصريح، وتطبق الحماية في الخلفية.
- للمحتوى المنشور عنوان ومحتوى عربي وإنجليزي؛ عند نقص لغة يظهر تنبيه بالنواقص مع خيارين: نشر اللغة المكتملة الآن، أو إكمال الترجمة أولًا. تبقى آخر نسخة منشورة للغة الناقصة حتى تكتمل، وإن لم توجد نسخة منشورة فلا تعرض مسودتها للعامة. لا يترجم محتوى العميل تلقائيًا.

### الجاهز والشراء

- يظهر التوفر للعميل بكلمات «متوفر» أو «آخر قطعة» أو «غير متوفر» دون أرقام الأرصدة؛ آخر قطعة تعني متاحًا واحدًا في نطاق البيع المختار بعد الحجوزات. لا تكشف الواجهة العامة الموجود أو المحجوز أو الحركات، ويعاد فحص المتاح عند التأكيد.
- تأكيد الجوال برمز عند الشراء ينشئ جلسة دخول العميل لمتابعة طلبه؛ يستخدم الحساب القائم المثبت إن وجد، أو ينشئ الحساب مرة واحدة بعد استكمال بياناته المطلوبة وفحص فرادة الجوال والبريد. تعارض البيانات يحال للمعالجة دون دمج أو ربط حساب آخر تلقائيًا. رمز الدخول لا يثبت الدفع أو يؤكد الطلب أو يحجز المخزون وحده، ولا يمنح شخص اتصال الجهة وصولًا لمجرد وجود جواله في قائمة الاتصالات.
- المتجر اختياري عند توفر وحدة الجاهز. يمكن للجهة بيع الجاهز من المعرض دون نشر متجر.
- السلة جاهز فقط وتختار النسخة والكمية؛ السعر والتوفر يعاد التحقق منهما عند التأكيد. المخصص ينشئ اهتمامًا أو طلبًا مستقلًا بلا سلة مختلطة معقدة.
- يؤكد طلب الجاهز مع حجز الكمية ذريًا. للدفع الإلكتروني غير الفوري مهلة حجز واضحة، افتراضيًا 30 دقيقة؛ انتهاء المهلة يفك الحجز فقط إذا لم تتأكد عملية دفع أو تبقَ عملية معلقة للتحقق.
- وصول نجاح دفع متأخر بعد فك الحجز لا يبيع رصيدًا غير موجود؛ يعلق الطلب للمعالجة ويظهر للعميل «جارٍ تأكيد طلبك»، ثم يعاد الحجز إن توفر أو يعالج الرد.
- طرق الاستلام بسيطة: استلام من الفرع أو توصيل بمناطق ورسوم محددة إن فعلته الجهة. لا يفترض ربط شركات شحن أو تحسين مسارات.
- عند إزالة وحدة الجاهز يغلق المتجر فورًا ويمنع التأكيد الجديد من كل القنوات، وتبقى متابعة الطلبات والدفع والتسوية للقائم ممكنة.

### الحساب والهوية

- يدخل العميل برمز يرسل إلى جواله دون كلمة مرور، والبريد الموثق المرتبط بحسابه بديل؛ لا تظهر إلا الطلبات المرتبطة بهويته المثبتة ومنح الوصول الصريحة. الرمز قصير الصلاحية ولمرة واحدة، مع حدود للمحاولات وإعادة الإرسال، ولا يكشف الرد العام وجود الحساب. لا يتيح تعذر الجوال إدخال بريد آخر للوصول إلى حساب قائم، ولا يثبت تأكيد الجوال ملكية البريد تلقائيًا.
- داخل مساحة المنشأة، لكل حساب جوال واحد وبريد واحد فريدان بعد توحيد الصيغة، مع إثبات الملكية قبل ربط الطلبات أو تغيير وسيلة دخول. لا يظهر وجود حساب عند جهة أخرى.
- لا يلزم تنشيط حساب العميل لتسجيله وفتح طلبه بواسطة الموظف. تفعيل الدخول لا يربط طلبًا لمجرد تطابق الاسم.
- العميل يرى طلباته المصرح بها فقط. حساب جهة تجارية لا يكشف كل طلباتها لأي شخص اتصال؛ يحدد المخول الأشخاص المسموح لهم.
- مع قاعدة مستقلة لكل جهة، لا نبني هوية مركزية للعملاء في الإصدار الأول. الحساب وعلاقة الطلب محليان لكل جهة، وموقعها وتطبيق العملاء لاحقًا يستخدمان الهوية نفسها داخلها.
- يمكن تعديل الملف والعناوين وتفضيلات اللغة والإشعارات وتسجيل الخروج؛ بيانات الاتفاق السابقة تبقى محفوظة.

### تجربة العميل

- الصفحة تبدأ بـ«مطلوب منك» إن وجد: مبلغ للدفع أو مستند للموافقة أو موعد للتأكيد، مع زر مباشر. إن لا يوجد إجراء مطلوب، يظهر التقدم المتوقع والتحديث الأخير.
- «طلباتي» تميز الجاهز والمخصص، وتعرض لكل طلب الحالة ورقمه وما يحتاجه العميل دون بيانات داخلية.
- رحلة الطلب تجمع الأعمال في محطات واضحة للعميل، ولا تعرض قائمة المهام أو أسماء الأقسام الداخلية. تأخر طلب لا يولد موعدًا حسابيًا غير موثوق.
- يميز الموعد المؤكد عن التقديري، ويظهر سبب التغيير المناسب للعميل عند تحديثه. لا تعد كل دفعة أو تأخر يساوي تلقائيًا عدد أيام في التسليم.
- المبلغ المستحق وطرق الدفع و«دفعت بالتحويل؟ أرفق الإيصال» داخل الطلب نفسه. يظهر الإثبات قيد المراجعة حتى التأكيد، ثم السند.
- التصميم والعقد والعرض يفتح كل منها بمحتواه المطلوب اعتماده وملاحظات العميل، دون تنزيل ملفات متعددة للعثور على النسخة الصحيحة.
- يرى العميل المواعيد ويؤكدها أو يطلب تغييرها. يمكنه اختيار بديل من فترات أتاحتها الجهة فعليًا، دون إنشاء موعد مؤكد متعارض.
- المستندات المسموح بها منظمة حسب النوع والتاريخ، مع جهة تواصل أو مشرف طلب إن سمحت الجهة، و«الدعم»: قائمة تذاكره وحالاتها، و«تذكرة جديدة» مرتبطة بطلب أو «بلا طلب: سؤال عام»، وتفتح أيضًا من «أبلغ عن مشكلة» في صفحة الطلب مع تعبئة مرجعه. النوع مستقل عن ربط الطلب ويختار من مشكلة أو سؤال أو طلب أو أخرى. يرى بيانات تذكرته ورسائله والردود العامة فقط دون الملاحظات الداخلية، ويصله إشعار بالبريد وSMS، وردّه بعد الحل يعيد فتح التذكرة نفسها. تعثر الإشعار لا يلغي الرد المتاح في الحساب.
- الموقع متجاوب بطول طبيعي وعرض المتصفح، ويدعم العربية والإنجليزية. مساحة العميل («حسابي») جزء من الموقع برأسه نفسه، فيصل العميل إلى الموقع والمتجر من أي صفحة عند إتاحته ضمن الباقة؛ أقسامها: نظرة عامة تبدأ بـ«مطلوب منك»، وطلباتي، والمستندات، والدعم، والإعدادات، دون نسخ قائمة الإدارة. يحافظ عرض الجوال على هذه الروابط بطريقة مناسبة لمساحته.

## الثيم والهوية

- تستلم الجهة Alpha جاهزًا وفق نظام تصميم OpsOne. تعدل شعارها وأيقونة الموقع ولون العلامة ووضع عرض موقعها ومساحة العميل من خيارات مفهومة؛ يشتق النظام الألوان المرتبطة ويحافظ على القراءة في الفاتح والداكن.
- كل خيار يبين أماكن أثره. تنعكس هوية الجهة على الموقع ومساحة العميل، ولمسات اللون وتعريف الجهة في الإدارة، مع بقاء شعار OpsOne وبنية الإدارة المعتمدة. وضع الإدارة يتبع مستخدمها، وتفضيل العميل الشخصي يتقدم على افتراضي الموقع.
- معاينة خاصة لصفحات الموقع فقط، باختيار الصفحة والجوال أو الحاسوب واللغة؛ لا تعرض لوحة الإدارة داخل المعاينة، ويبين أثرها نصيًا. ثم حفظ مسودة أو تطبيق بصلاحية مستقلة. الاستعادة تجهز الافتراضي للمعاينة والتطبيق دون حذف المحتوى؛ الفشل يبقي المنشور السابق.
- لا كود حر أو ثيمات خارجية أو تعديل يدوي لكل لون ومسافة. محتوى الصفحات وترتيب أقسامها في محررها، والمستندات الصادرة تبقى محفوظة بهويتها وقت الإصدار. لا إعدادات خاصة بكل نشاط أو باقة لهذه الأساسيات.

## رابط السلة وطلب الإلغاء

- يفتح رابط الموظف سلة جاهز دون كشف بيانات عميل آخر. يفحص الصلاحية والسعر والخصم والمخزون عند الإتمام؛ محاولة واحدة جارية، ولا حجز عند إصدار الرابط. تعديل محتوى دفع جارٍ ينتظر حسمه.
- العميل يطلب الإلغاء من طلبه مع السبب، ويتابع قرار الإدارة. لا يلغي بنفسه؛ يمكن سحب الطلب قبل القرار. قبول الإدارة يظهر الإلغاء وأي تسوية قائمة، والرفض يظهر سببه بوضوح.
- لا تمنح صفحة العميل صلاحية موظف؛ شراء العميل وطلب إلغائه يستخدمان وصوله إلى طلبه فقط. بيانات العمولة وحدود الموظف داخلية.

## مخططات العمليات الأساسية

مخططات BPMN لقراءة العمل بين المسؤولين والخدمات، وليست إعدادًا يحرره التاجر أو محركًا إضافيًا. المخطط مع جدول حالاته وحدة واحدة: يعرض الرسم القرارات الرئيسية، وتحدد الجداول النتائج الجزئية والتزامن والفشل والعدول. التكرار أو وصول حدث قديم يعالجان وفق ضوابط الترابط في الـ SRS، دون إعادة أثر. المربع إجراء، والدائرة بداية أو نهاية، والمعين قرار حصري أو توازٍ بعلامة الجمع.

## معايير القبول

- الـ **WEB-01:** اهتمام دون حساب يعطي مرجعًا ولا يكرر الطلب عند إعادة المحاولة.
- الـ **WEB-02:** العميل لا يصل لطلب غير مصرح به عبر رابط مباشر أو ملف أو بحث.
- الـ **WEB-03:** الموافقة والدفع وتأكيد الموعد تبدأ من مطلوب العميل وتظهر نتيجتها الصحيحة.
- الـ **WEB-04:** نقص مخزون عند التأكيد يمنع البيع؛ تعليق نتيجة الدفع لا يظهر رفضًا مؤكدًا.
- الـ **WEB-05:** منع المتجر لا يمنع متابعة الطلبات الجاهزة القائمة أو سدادها.
- الـ **WEB-06:** حماية صفحات النظام تطبق على الحذف والتعطيل والتحرير عبر API أيضًا.
- الـ **WEB-07:** تغيير حساب أو عنوان لا يعيد كتابة مستند معتمد؛ جميع الرسائل والاتجاهات تدعم اللغتين.
