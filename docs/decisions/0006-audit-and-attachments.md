# ADR-0006: سجل التدقيق والمرفقات الخاصة

- **الحالة:** مقبول (Q-23 = (أ): قرص محلي خاص داخل نشر المنشأة الآن، خلف `Storage`)
- **التاريخ:** 2026-10-30
- **المرحلة:** P3 الجزء أ (الخدمات المشتركة 09)
- **المعرفات:** SHR-10، SHR-11، NFR-14؛ P-63

## السياق

كل نطاق تجاري يحتاج سجل تدقيق لا يُعدَّل ولا يُحذف (SHR-11، «لا يمنح المدير نفسه محو التدقيق»)، وملفات خاصة بنوع
وحجم وصلاحية وسعة باقة (SHR-10، NFR-14). `state_transitions` (ADR-0005) يسجل الانتقالات فقط ولا يحمل الفرق ولا
بيانات الطلب، وتغييرات مثل تعديل فرع أو الإعدادات ليست انتقالات.

## القرار

### التدقيق

| العنصر | القرار |
|---|---|
| الجدول | `audit_events`: الفعل (`AuditAction` enum، القيمة ثابتة)، المجال، الفاعل (المعرف + الاسم وقتها)، المصدر، السجل (النوع/المعرف/التسمية وقتها)، القسم، `before`/`after` (JSON)، السبب، `ip_hash`، المتصفح، `request_id`، الوقت (UTC، دقة ميكروثانية) |
| النطاق | `audit_event_branches`: فروع السجل وقت الحدث، تُشتق من `ScopedRecord`. حدث بلا فرع = على مستوى المنشأة ولا يراه إلا نطاق «كامل الجهة» |
| الإلحاق فقط | النموذج يرفض `update`/`delete`، و**triggers** في القاعدة (MariaDB `SIGNAL 45000`، SQLite `RAISE(ABORT)`) ترفض UPDATE وDELETE على الجدولين. لا مفاتيح أجنبية (الإجراءات المرجعية تعيد كتابة الصفوف)؛ الأسماء تُحفظ نسخةً |
| الواجهة | `Audit::record(AuditAction, $subject, $actor, before:, after:, reason:, source:)`؛ ترمي `LogicException` خارج transaction، فالأثر والتدقيق يُلتزمان أو يُلغيان معًا |
| التنقيح | المستدعي يمرر الحقول المهمة فقط؛ ثم تُستبدل مفاتيح الأسرار (password، token، secret، `*_hash`، two_factor، recovery، otp، proof، signature، بيانات بطاقة) بـ `[redacted]` وتُقص النصوص الطويلة، ويُعاد التنقيح عند العرض. البريد الكامل للمدعو لا يُخزَّن (`s***@domain`). عنوان IP يُخزَّن HMAC-SHA256 بمفتاح التطبيق لا نصًا |
| الربط في P2 | الدعوات (إنشاء، قبول، إلغاء، تجديد، دعوة المالك وتثبيته)، العضوية (تعطيل، إعادة تفعيل، تغيير الأدوار والمنح)، قوالب الأدوار، نقل الملكية (طلب، قبول، رفض، إلغاء)، الفروع (إنشاء، تعديل، تعطيل، إعادة تفعيل)، ملف المنشأة وخطوات الإعداد واكتماله، تثبيت الترخيص، رفع مرفق. الانتهاءات الآلية تبقى في `state_transitions` فقط |
| الشاشة | `AuditLog` في `/org/audit` (P-63): ترقيم من الخادم (25)، مرشحات المجال والفاعل والتاريخ (بمنطقة المنشأة) والبحث، درج تفاصيل يعيد فحص P-63 على الحدث نفسه. لا مسار تعديل أو حذف |

### المرفقات

| العنصر | القرار |
|---|---|
| التخزين | قرص `attachments` (محلي، `storage/app/private/attachments`، `serve=false`) عبر `ATTACHMENTS_DISK`؛ تحويله إلى S3-compatible لاحقًا تغيير إعداد فقط. اسم الملف على القرص UUID عشوائي |
| النموذج | `attachments`: `uuid` (المعرف الوحيد في الروابط)، مالك متعدد الأشكال، الغرض، الحجم، SHA-256، الرافع. المالك ينفذ `Files\Contracts\AttachmentOwner` (صلاحية العرض وصلاحية الرفع على السجل) |
| الفحص | قائمة سماح (`config/attachments.php`: pdf، png، jpg/jpeg، webp، docx، xlsx) + نوع MIME المكتشف من المحتوى (finfo) + البايتات السحرية؛ الثلاثة يجب أن تتفق. الحد 10 ميجابايت للملف. القاعدة `AllowedAttachment` لاستخدامها في Form Requests، والخدمة تعيد تشغيلها |
| السعة | `LicenseLimits::reserveStorage()` داخل transaction الإدراج (قفل صف المنشأة) مقابل `storage_mb`؛ تجاوزها = `LicenseLimitReached('storage')` برسالة ar/en، ولا يبقى ملف على القرص. شاشة الباقة تعرض الاستخدام المقيس |
| التنزيل | `files.download`: رابط موقع مؤقت (5 دقائق افتراضيًا) مربوط بالمستخدم (`u`)، ويتطلب جلسة. وقت التنزيل يُعاد فحص صلاحية العرض على السجل المالك؛ خارج النطاق أو مالك مفقود = 404 (لا كشف للوجود)، رابط لمستخدم آخر أو منتهٍ أو معدَّل = 403. الاستجابة `attachment` مع `nosniff` و`no-store` وCSP `sandbox` |

## العواقب

- إنشاء triggers في MariaDB يتطلب صلاحية `TRIGGER` لمستخدم القاعدة (متاحة لمستخدم Compose). إن فُعِّل binary logging
  في بيئة ما دون `SUPER`، يلزم `log_bin_trust_function_creators=1` قبل الترحيل؛ وإلا يفشل الترحيل صراحةً (مقصود).
- لا يمكن تصحيح حدث تدقيق؛ التصحيح حدث جديد. حذف بيانات شخصية من التدقيق (إن طُلب قانونيًا) يحتاج إجراءً موثقًا
  بصلاحيات قاعدة استثنائية وليس جزءًا من التطبيق.
- لا مسار رفع HTTP عام بعد: كل نطاق يضيف مسار رفعه مع Form Request يستخدم `AllowedAttachment` ويستدعي
  `AttachmentService::store()`. حذف المرفقات وحماية ملفات الإثبات (SHR-10) يأتيان مع أول نطاق يملك ملفات.
- فحص الفيروسات غير مشمول؛ يمكن إضافته خطوةً في `AttachmentService` قبل الإدراج.
- استثناء NFR-14 لاستكمال الإثباتات عند امتلاء السعة (احتياطي معلوم وتنبيه المالك) مؤجل إلى أول نطاق إثبات.
