# ADR-0004: عقد الترخيص الموقّع والتحقق منه داخل تطبيق المنشأة

- **Status:** Accepted (توصيات Q-12..Q-15 الافتراضية؛ قابلة للمراجعة دون كسر العقد بفضل رقم الإصدار)
- **Date:** 2026-10-27
- **المراجع:** ADR-0002، ADR-0003، النطاق 08، M-19، SRS-SUB-06/11/12/20، الباقات وحدود الاستخدام
  (`docs/analysis/source/`)

## السياق

التطبيق المركزي (ADR-0003) يوقّع الترخيص، وتطبيق المنشأة يتحقق منه فقط. لا يوجد العقد بعد في أي طرف، لذا
يُثبَّت هنا أولًا ثم يُنفَّذ في `app/Licensing/`. M-19 يحدد الحالات: مجهز غير مفعل، صالح، سماح، إتمام القائم،
قراءة وتصدير، يحتاج معالجة.

## القرار

### 1. الصيغة (Q-12)

ملف JSON واحد («الظرف») يحمل الحمولة كبايتات موقّعة كما هي، فلا حاجة لتطبيع JSON (canonicalization):

```json
{
  "format": "opsone-license",
  "kid": "opsone-production-2026",
  "payload": "<base64url(UTF-8 JSON bytes)>",
  "signature": "<base64url(Ed25519 detached signature)>"
}
```

- الخوارزمية: Ed25519 عبر `sodium_crypto_sign_verify_detached`.
- الرسالة الموقّعة: `"OPSONE-LICENSE\n" . payload_bytes` (فصل سياق يمنع إعادة استعمال توقيع من غرض آخر).
- `kid` يختار المفتاح العام؛ يسمح بتدوير المفتاح دون تغيير الصيغة.
- الحد الأقصى لحجم الملف 64 KB.

الحمولة، `schema_version = 1`:

| الحقل | النوع | ملاحظات |
| --- | --- | --- |
| `schema_version` | int | الإصدارات المدعومة: `[1]`؛ غيرها يُرفض |
| `license_id` | string | معرّف هذا الإصدار من الترخيص |
| `facility_id` | string | المنشأة |
| `deployment_id` | string | النشر المعزول (ADR-0002) |
| `domains` | string[] | نطاقات النشر؛ يجب أن يحتوي مضيف `APP_URL` |
| `plan` | string | `basic` / `growth` / `scale` (أسماء تجارية غير نهائية) |
| `capabilities` | string[] | قدرات الباقة، مثل `ready_goods`، `branch_comparisons` |
| `limits` | object | `seats`، `branches`، `storage_mb` (أعداد صحيحة ≥ 0) |
| `activation_id` | string\|null | مرجع التفعيل/التسليم؛ `null` = ترخيص تجهيز غير مفعل |
| `starts_at` | ISO-8601 UTC\|null | بداية المدة = واقعة التسليم؛ `null` قبل التفعيل |
| `ends_at` | ISO-8601 UTC\|null | نهاية المدة التعاقدية |
| `grace_days` | int | 7 افتراضيًا (Q-15) |
| `wind_down_days` | int | 30 افتراضيًا (Q-15) |
| `retention_days` | int | مدة «قراءة وتصدير» بعد إتمام القائم؛ من العقد التجاري |
| `issued_at` | ISO-8601 UTC | وقت التوقيع؛ يمنع إعادة تركيب ترخيص أقدم من آخر ترخيص موثوق |

الحقول الإضافية غير المعروفة تُتجاهل داخل الإصدار نفسه؛ أي تغيير في معنى حقل قائم = إصدار جديد.

### 2. التحقق

`LicenseVerifier` يرفض بسبب صريح (`LicenseProblem`): ملف مفقود، JSON تالف أو ظرف ناقص، `kid` غير معروف،
توقيع غير صالح، إصدار غير مدعوم، حمولة ناقصة/غير صالحة، نطاق غير مطابق لمضيف `APP_URL`، `deployment_id`
غير مطابق (حين يُضبط `LICENSE_DEPLOYMENT_ID`)، ترخيص أقدم من آخر ترخيص موثوق (`superseded`).

### 3. المدة والحالة (M-19، Q-15)

لحظة التقييم `t`:

| الشرط | الحالة | القدرات | عمل جديد |
| --- | --- | --- | --- |
| غير مفعل أو `t < starts_at` | `provisioned` | لا | لا |
| `t < ends_at` | `active` | نعم | نعم |
| `t < ends_at + grace_days` | `grace` | نعم | نعم |
| `t < … + wind_down_days` | `wind_down` | نعم (إتمام القائم) | لا |
| بعد ذلك | `expired` (قراءة وتصدير حتى `retention_days`) | لا | لا |
| أي خلل تحقق أو ساعة غير موثوقة | `needs_attention` | من آخر حالة موثوقة فقط | حسب آخر حالة موثوقة |

لا حذف تلقائي للبيانات في أي حالة. `daysRemaining()` = الأيام المتبقية في المرحلة الحالية (تقريب للأعلى).

### 4. السلوك عند الخلل (Q-14، M-19-T05)

- الدخول مسموح دائمًا مع لافتة «يحتاج معالجة»؛ لا قفل كامل.
- تُحفظ **آخر حالة موثوقة** (الظرف الموقّع نفسه) في جدول `license_states` وفي الكاش؛ الجدول يبقيها بعد مسح الكاش.
- في `needs_attention` تُقيَّم آخر حالة موثوقة عند **الوقت الرتيب** `max(now, last_seen_at)`، فلا يُمدَّد الترخيص
  بإرجاع الساعة («دون تمديد خفي»). بلا حالة موثوقة سابقة تُرفض كل القدرات.
- **الساعة غير موثوقة** إذا `now < last_seen_at - tolerance` (افتراضي 300 ثانية) أو `issued_at > now + tolerance`.
  `last_seen_at` يتقدم فقط ويُكتب كل 60 ثانية على الأكثر.

### 5. المفاتيح والبيئات (Q-13)

- لا تعطيل للتحقق في أي بيئة.
- الإنتاج: `LICENSE_PUBLIC_KEY` (base64 لمفتاح Ed25519 العام، 32 بايت) و`LICENSE_KEY_ID` من البيئة. لا مفتاح خاص
  في تطبيق المنشأة.
- التطوير: زوج مفاتيح اختبار **غير سري** مُثبت في `app/Licensing/Development/DevelopmentKeypair.php` بـ `kid`
  ثابت `opsone-dev-insecure`. مفتاحه العام **لا يُوثق إلا** حين `app()->environment(['local','testing'])`؛ في
  dev/stage/prod يُرفض أي ترخيص موقّع به (`unknown_key`). هذا استثناء محدد لقاعدة ADR-0003 «لا مفاتيح في
  المستودع»، لأن المفتاح لا يمنح ثقة في أي بيئة منشورة. dev/stage تستعمل ترخيصًا من التطبيق المركزي بمفتاح غير
  إنتاجي يُحقن بالطريقة نفسها.
- `php artisan license:dev-issue` يوقّع بمفتاح الاختبار ويرفض العمل خارج local/testing.

### 6. التركيب

- المسار: `LICENSE_PATH` (افتراضي `storage/app/private/license.json`).
- `php artisan license:install <path>` يتحقق أولًا ثم يكتب الملف ذريًا ويحدّث الحالة الموثوقة (M-19-T04/T06)؛
  الملف غير الصالح لا يُكتب. `php artisan license:status` للتشخيص.

### 7. الواجهة البرمجية

`App\Licensing\CurrentLicense`: `status()`، `allows(string $capability): bool`، `limit(string $key): ?int`،
`daysRemaining(): ?int`، `acceptsNewWork(): bool`، `problem()`. `limit()` يعيد `null` حين لا يوجد حد مُثبت،
ويجب أن يعامله المستهلك كمنع للزيادة. Gate الصلاحيات (`app/Access/`) يستهلك هذه الواجهة لاحقًا.

## البدائل

- **JWT/RS256:** مفاتيح أكبر ومكتبة إضافية وخيارات خوارزمية قابلة للخطأ (`alg`)؛ Ed25519 مدمج في PHP.
- **تعطيل التحقق محليًا:** يخفي أخطاء العقد حتى الإنتاج؛ مرفوض.
- **قفل كامل عند الخلل:** يخالف M-19-T05 ويحوّل خلل الساعة إلى توقف أعمال.

## النتائج

- التطبيق المركزي يجب أن ينتج الظرف نفسه حرفيًا (الرسالة الموقّعة، base64url، الحقول).
- `superseded` يعني أن أي ترخيص جديد يجب أن يحمل `issued_at` أحدث.
- القيم التجارية (أسماء الباقات، القدرات، `retention_days`) تبقى من العقد التجاري والترخيص، لا من الكود.
